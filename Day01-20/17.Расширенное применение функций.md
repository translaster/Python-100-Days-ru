## Расширенное применение функций

В предыдущей главе мы изучили функции высшего порядка в Python, и, я полагаю, что вы получили более глубокие знания об определении и применении функций. В этой главе мы продолжим знакомить вас с функциями, одной из которых являются декораторы синтаксиса в Python, а другой - рекурсивные вызовы функций.

### Декораторы

В Python декоратор - это синтаксическое явление "**декорирование одной функции другой и наделение ее дополнительными возможностями**". Декоратор сам по себе является функцией, его аргументы - декорируемая функция, а возвращаемое значение - функция с декорированной функциональностью. Как вы уже наверняка поняли из предыдущего описания, декоратор - это функция более высокого порядка, аргументами и возвращаемым значением которой являются функции. Однако для начинающих изучать языки программирования понятие декоратора все еще остается непонятным, поэтому давайте начнем с простого примера, чтобы проиллюстрировать, что делает декоратор. Предположим, есть две функции с именами `downlaod` и `upload`, которые используются для скачивания и загрузки файлов соответственно, как показано ниже.

```python
import random
import time


def download(filename):
    """Скачивание файлов"""
    print(f'Начало скачивания {filename}.')
    time.sleep(random.random() * 6)
    print(f'{filename} полностью скачан.')

    
def upload(filename):
    """Загрузка файлов"""
    print(f'Начало загрузки {filename}.')
    time.sleep(random.random() * 8)
    print(f'{filename} полностью загружен.')

    
download('MySQL от удаления библиотек до запуска.avi')
upload('Python от введения до практики.pdf')
```

> **Примечание**: приведенный выше код имитирует время, необходимое для загрузки и выгрузки файла, впадая в спячку на случайный период времени, и не является реальной загрузкой и выгрузкой файлов по сети. Сетевая загрузка и выгрузка файлов также очень просто реализуется на Python, о чем мы поговорим позже.

Теперь у нас появилось новое требование: мы хотим знать, сколько времени требуется для вызова функций `download` и `upload`, чтобы загрузить и выгрузить файл. Я думаю, что многие уже догадались, мы должны записать время в начале выполнения функции и время после завершения вызова функции, два времени могут быть вычислены путем вычитания времени загрузки или выгрузки, код показан ниже.

```python
start = time.time()
download('MySQL от удаления библиотек до запуска.avi')
end = time.time()
print(f'Занимаемое время: {end - start:.2f} секунд')
start = time.time()
upload('Python от введения до практики.pdf')
end = time.time()
print(f'Занимаемое время: {end - start:.2f} секунд')
```

С помощью приведенного выше кода мы можем записывать время, затраченное на скачивание и загрузку файлов, но я не знаю, заметили ли вы, что приведенный выше код, который записывает время, вычисляет и отображает время выполнения, является дублирующим кодом. Любой человек, имеющий опыт программирования, знает, что **дублирование кода - корень всех зол**, так есть ли способ записывать время выполнения функции простым и элегантным способом без написания дублирующего кода? В Python декораторы являются идеальным решением для такого рода проблем. Используя синтаксис декораторов, мы можем инкапсулировать код, не имеющий отношения к исходным функциям учета времени выполнения (скачивание и загрузка), в одну функцию, так что если функциям `upload` и `download` понадобится отслеживать время выполнения, мы можем просто применить декоратор непосредственно к этим двум функциям. Поскольку выше мы упоминали, что декоратор - это функция более высокого порядка, аргументами и возвращаемыми значениями которой являются функции, назовем декоратор учета времени `record_time`, а его общая структура должна выглядеть следующим образом.

```python
def record_time(func):
    
    def wrapper(*args, **kwargs):
        
        result = func(*args, **kwargs)
        
        return result
    
    return wrapper
```

Уверен, вы заметили, что аргумент `func` в функции `record_time` представляет собой декорированную функцию, а функция `wrapper`, определенная внутри функции, является функцией с декором, она будет выполнять декорированную функцию `func`, а также должна вернуть значение, которое производит выполнение функции в конце. Не знаю, заметили ли вы, но в приведенном выше коде я оставил две пустые строки в строке 4 и 6, что означает, что мы можем добавить код в эти места для реализации дополнительной функциональности. Функция `record_time` в конечном итоге возвращает эту декорированную функцию `wrapper` и заменяет ею исходную `func`. Когда исходная `func` декорируется функцией `record_time`, мы фактически вызываем функцию `wrapper` при ее вызове, что и позволяет нам получить дополнительную функциональность. Аргументы функции `wrapper` особенны тем, что поскольку мы заменяем исходную `func` на `wrapper`, но не знаем точно, какие аргументы примет исходная `func`, мы принимаем их все как есть, через аргументы переменных и ключевых слов, а затем передаем их `func` как есть при ее вызове. Следует также подчеркнуть, что язык Python поддерживает вложенные определения функций. Так, например, мы можем определить функцию `wrapper` внутри функции `record_time` - операция, которая не поддерживается во многих языках программирования.

Прочитав эту структуру, мы можем записать функцию `record_time` в этот декоратор с помощью кода, показанного ниже.

```python
import time


def record_time(func):

    def wrapper(*args, **kwargs):
        # Запись времени запуска перед выполнением декорированной функции
        start = time.time()
        # Выполнение декорированной функции и получение возвращаемого значения
        result = func(*args, **kwargs)
        # Запись времени окончания выполнения декорированной функции
        end = time.time()
        # Вычисление и отображение времени выполнения декорированной функции
        print(f'{func.__name__} время выполнения: {end - start:.2f} секунд')
        # Возврат значения декорированной функции
        return result
    
    return wrapper
```

Написание декоратора - это немного муторно, но это раз и навсегда утомительная операция. В будущем, когда у нас возникнет необходимость регистрировать время выполнения функции, мы можем просто добавить вышеупомянутый декоратор. Есть два способа использования вышеупомянутой функции-декоратора, первый - это прямой вызов функции-декоратора, передача декорированной функции и получение возвращаемого значения, мы можем использовать это возвращаемое значение непосредственно вместо оригинальной функции, тогда в вызове были предоставлены декоратором дополнительные возможности (запись времени выполнения), для понимания попробуем следующий код.

```python
download = record_time(download)
upload = record_time(upload)
download('MySQL от удаления библиотек до запуска.avi')
upload('Python от введения до практики.pdf')
```

В Python есть гораздо более удобный **синтаксический сахар** (синтаксис, добавляемый в язык программирования, который не влияет на функциональность языка, но используется более методично и делает код более читаемым, что мы называем «синтаксическим сахаром» или "синтаксисом с сахарным покрытием"), который вы можете использовать для размещения функции-декоратора непосредственно на декорируемой функции, используя `@decorator function`, что имеет тот же эффект, что и код выше. Мы привели полный код, чтобы вы могли еще раз увидеть, как мы определяем и используем декораторы.

```python
import random
import time


def record_time(func):

    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f'{func.__name__} время выполнения: {end - start:.2f} секунд')
        return result

    return wrapper


@record_time
def download(filename):
    print(f'Начало скачивания {filename}.')
    time.sleep(random.random() * 6)
    print(f'{filename} скачан полностью.')


@record_time
def upload(filename):
    print(f'Начало загрузки {filename}.')
    time.sleep(random.random() * 8)
    print(f'{filename} загружен полностью.')


download('MySQL от удаления библиотек до запуска.avi')
upload('Python от введения до практики.pdf')
```

В приведенном выше коде мы добавили декораторы к функциям `download` и `upload` с помощью синтаксического сахара декораторов, а декорированные функции `download` и `upload` на самом деле являются функциями-обертками, которые мы вернули в декораторе, и их вызов на самом деле является вызовом функции-обертки, поэтому функция записи в ремя выполнения функции.

Если в коде есть места, где мы хотим убрать роль декоратора для выполнения исходной функции, то при определении функции-декоратора нужно проделать дополнительную работу. Функция `wraps` модуля `functools` стандартной библиотеки Python также является декоратором, и мы помещаем в нее функцию `wrapper`. Этот декоратор помогает нам сохранить функцию до того, как она была декорирована. Этот декоратор помогает нам сохранить функцию до того, как она была декорирована, так что, когда нам нужно отменить декоратор, мы должны получить функцию до того, как она была декорирована, используя атрибут декорированной функции `__wrapped__`.

```python
import random
import time

from functools import wraps


def record_time(func):

    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f'{func.__name__} время выполнения: {end - start:.2f} секунд')
        return result

    return wrapper


@record_time
def download(filename):
    print(f'Начало скачивания {filename}.')
    time.sleep(random.random() * 6)
    print(f'{filename} скачан успешно.')


@record_time
def upload(filename):
    print(f'Начало загрузки {filename}.')
    time.sleep(random.random() * 8)
    print(f'{filename} успешно загружен.')


# Запись вызовов декорированных функций времени выполнения
download('MySQL от удаления библиотек до запуска.avi')
upload('Python от введения до практики.pdf')
# Отмененная роль декоратора времени выполнения
download.__wrapped__('MySQL от удаления библиотек до запуска.pdf')
upload.__wrapped__('Python от введения до практики.pdf')
```

**Сами функции декоратора также могут быть параметризованными**, что означает, что декоратор может быть настроен с помощью параметров, передаваемых вызывающей стороной, что мы объясним позже при его использовании.

### Рекурсивные вызовы

Python позволяет функциям быть вложенными, функциям вызывать друг друга, а функции вызывать себя прямо или косвенно. Функция, вызывающая саму себя, называется рекурсивной, так в чем же смысл рекурсивного вызова? На самом деле существует множество задач, определение которых само по себе является рекурсивным определением, например, факториал, о котором мы говорили ранее, где факториал целого неотрицательного числа `N` - это факториал `N`, умноженный на `N-1`, то есть $\small{N! = N \times (N-1)!}. $, понятие факториала встречается как в левой, так и в правой части определения, так что это рекурсивное определение. Так как это так, мы можем написать функцию для нахождения факториала с помощью рекурсивного вызова, как показано в коде ниже.

```python
def fac(num):
    if num in (0, 1):
        return 1
    return num * fac(num - 1)
```

В приведенном выше коде функция `fac` вызывается снова в функции `fac`, что называется рекурсивным вызовом. Условие `if` во 2 строке кода называется условием сходимости рекурсии, которое просто означает, когда следует завершить рекурсивный вызов функции. При вычислении факториала, если факториал вычисляется в `0` или `1`, рекурсивный вызов будет остановлен, и `1` будет возвращено напрямую; `num * fac(num - 1)` в 4 строке кода является рекурсивной формулой, которая представляет собой рекурсивное определение факториала. Ниже мы кратко проанализируем, как будет выглядеть весь процесс, если мы используем `fac(5)` для вычисления факториала числа `5`.

```python
# Рекурсивный вызов функции в стеке
# 5 * fac(4)
# 5 * (4 * fac(3))
# 5 * (4 * (3 * fac(2)))
# 5 * (4 * (3 * (2 * fac(1))))
# Остановка рекурсивной функции в стеке
# 5 * (4 * (3 * (2 * 1)))
# 5 * (4 * (3 * 2))
# 5 * (4 * 6)
# 5 * 24
# 120
print(fac(5))    # 120
```

Обратите внимание, что вызовы функций сохраняют текущее выполнение кода через структуру данных в памяти, называемую «стек», которая используется для восстановления предыдущего выполнения в конце вызова функции. Стек - это структура данных, где первая функция, вошедшая в стек, вернется последней, а последняя функция, вошедшая в стек, вернется первой. Например, если вызывается функция с именем `a`, в теле выполнения функции `a` вызывается функция `b`, а в теле выполнения функции `b` вызывается функция `c`, то функция, которая первой входит в стек, - это `a`, а функция, которая первой выходит из стека, - это `c`. Каждый раз, когда вы входите в вызов функции, стек увеличивается на один слой стековых фреймов - структур, о которых мы только что упоминали и которые хранят текущее место выполнения кода; каждый раз, когда вызов функции завершается, стек уменьшается на один слой стековых фреймов. Как правило, пространство стека в памяти очень мало, поэтому слишком большое количество рекурсивных вызовов может привести к переполнению стека, поэтому **рекурсивные вызовы должны быть уверены, что они быстро сходятся**. Мы можем попробовать запустить `fac(5000)` и посмотреть, получим ли мы ошибку `RecursionError` с сообщением `maximum recursion depth exceeded in comparison`, которая на самом деле является переполнением стека.

Если мы используем официальный интерпретатор Python (CPython), то максимальная глубина стековой структуры для вызовов функций по умолчанию установлена на `1000` уровней. Если эта глубина будет превышена, возникнет описанная выше `RecursionError`. Конечно, мы можем использовать функцию `setrecursionlimit` модуля `sys для изменения максимальной глубины рекурсивных вызовов, но мы не рекомендуем этого делать, потому что рекурсия должна быстро сходиться, иначе нам следует подумать об использовании круговой рекурсии вместо рекурсии.

Приведем еще один пример создания ряда Фибоначчи, о котором мы говорили ранее: поскольку первые два числа ряда Фибоначчи равны `1`, а начиная с третьего числа и далее каждое число является суммой первых двух чисел, сложенных вместе, это можно записать как `f(n) = f(n - 1) + f(n - 2)`, что, очевидно, является еще одним определением рекурсии, поэтому мы можем использовать следующую функцию рекурсивного вызова для вычисления первого `n`-го числа Фибоначчи.

```python
def fib1(n):
    if n in (1, 2):
        return 1
    return fib1(n - 1) + fib1(n - 2)


for i in range(1, 21):
    print(fib1(i))
```

Напомню, что приведенный выше код для вычисления чисел Фибоначчи выглядит очень простым и понятным, но производительность его выполнения оставляет желать лучшего. Вы можете попробовать изменить второй параметр функции `range` в цикле `for` приведенного выше кода на `51`, то есть вывести первые 50 чисел Фибоначчи, и посмотреть, сколько времени это займет, а также оставить своё значение времени выполнения в разделе комментариев. Что касается того, почему это так медленно, то можете поразмышлять о причинах сами. Очевидно, что лучше получить ряд Фибоначчи напрямую, используя рекурсию цикла, код показан ниже.

```python
def fib2(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

В дополнение к этому мы можем оптимизировать рекурсивный код выше, используя функцию `lru_cache` из модуля `functools` стандартной библиотеки Python. Функция `lru_cache` - это функция-декоратор, которую мы помещаем поверх функции `fib1`, кэширующей результаты этой функции, чтобы она не повторялась при рекурсивных вызовах, что может сильно повлиять на производительность кода. Вы можете попробовать вывести первые 50 чисел Фибоначчи и посмотреть, сколько времени займет выполнение кода с декоратором, до встречи в разделе комментариев!

```python
from functools import lru_cache


@lru_cache()
def fib1(n):
    if n in (1, 2):
        return 1
    return fib1(n - 1) + fib1(n - 2)


for i in range(1, 51):
    print(i, fib1(i))
```

> **Подсказка**: Функция `lru_cache` является декоратором с параметрами, поэтому после `lru_cache` должны стоять круглые скобки при использовании синтаксиса декоратора в 4 строке кода выше. Функция `lru_cache` имеет очень важный параметр `maxsize`, который может быть использован для определения размера кэш-пространства, значение по умолчанию равно 128.

### Резюме

Декораторы - это специальный синтаксис в языке Python, **с помощью декораторов можно улучшать существующие функции**, что является очень полезной техникой программирования. С другой стороны, рекурсивные вызовы функций позволяют упростить сложные задачи на уровне кода, но **рекурсивные вызовы должны обращать внимание на условия сходимости и формулы рекурсии**; нахождение формулы рекурсии дает возможность использовать рекурсивные вызовы, а условие сходимости гарантирует, что рекурсивный вызов прекратится. Вызовы функций сохраняют обстановку и восстанавливают ее через пространство стека в памяти, которое обычно очень мало, поэтому **рекурсия, которая не сходится быстро, скорее всего, вызовет ошибку переполнения стека, что может привести к аварийному завершению программы**.
