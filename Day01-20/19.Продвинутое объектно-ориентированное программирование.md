## Продвинутое объектно-ориентированное программирование

Ранее мы рассмотрели некоторые основы объектно-ориентированного программирования в Python, и в этом разделе мы продолжаем разговор об объектно-ориентированном программировании.

### Декораторы видимости и свойств

Во многих объектно-ориентированных языках программирования свойства объекта обычно задаются как приватные или защищенные члены, а это означает, что вам не разрешается обращаться к ним напрямую; методы объекта обычно являются публичными, потому что публичный метод - это сообщение, которое объект может получить, и это вызывающий интерфейс, который объект открывает внешнему миру. Так называемая видимость доступа. В Python вы можете проиллюстрировать видимость доступа к атрибуту, добавив к имени атрибута объекта знак подчеркивания; например, вы можете использовать `__name` для обозначения атрибута private и `_name` для обозначения атрибута protected, как показано в следующем коде.

```python
class Student:

    def __init__(self, name, age):
        self.__name = name
        self.__age = age

    def study(self, course_name):
        print(f'{self.__name} обучается {course_name}.')


stu = Student('Кузнец', 20)
stu.study('Программирование на Python')
print(stu.__name)  # AttributeError: 'Student' object has no attribute '__name'
```

Последняя строка приведенного выше кода вызывает исключение `AttributeError` с сообщением `'Student' object has no attribute '__name'`. Как видите, атрибут `__name`, начинающийся с `__`, эквивалентен private и не может быть доступен напрямую извне класса, но к нему можно получить доступ в методе `study` внутри класса через `self.__name`. Важно отметить, что большинство людей, использующих Python, обычно не делают атрибуты объекта приватными или защищенными при определении класса; как гласит известная поговорка, "**We all consenting adults here**" (все мы взрослые люди), а взрослые люди могут нести ответственность за свое поведение, не ограничивая доступ к видимости с помощью самого языка Python. На самом деле, большинство программистов согласны с тем, что **открытость лучше закрытости** и что делать атрибуты объекта приватными необязательно, поэтому в Python нет строгих семантических оговорок, это означает, что приведенный выше код все равно имеет доступ к приватному атрибуту `__name` точно так же, как и `stu._Student__name`, если вы этого хотите, так что читатель может попробовать сам.

### Динамические свойства

Python - динамический язык, что в Википедии объясняется как «язык, структура которого может быть изменена во время выполнения, например, могут быть введены новые функции, объекты или даже код, удалены существующие функции или произведены другие структурные изменения». Динамические языки очень гибкие; популярные Python и JavaScript являются динамическими языками, как и PHP, Ruby и другие языки, которые не являются динамическими, такие как C и C++.

В Python вы можете динамически добавлять атрибуты к объектам, что является одной из привилегий Python как динамически типизированного языка, как показано в следующем коде. Важно отметить, что методы объекта по сути являются его атрибутами, и если вы посылаете объекту сообщение, которое не может быть принято, то возникающее исключение все равно будет `AttributeError`.

```python
class Student:

    def __init__(self, name, age):
        self.name = name
        self.age = age


stu = Student('Кузнец', 20)
stu.sex = 'мужской'  # Динамическое добавление атрибута sex к объекту student
```

Если вы не хотите динамически добавлять атрибуты к объекту при его использовании, то можете воспользоваться магией `__slots__` языка Python. Для класса `Student` можно указать `__slots__ = ('name', 'age')` в классе, чтобы объекты класса `Student` могли иметь только атрибуты `name` и `age`, а если вы попытаетесь динамически добавить любые другие атрибуты, то вызовете исключение, как показано в следующем коде.

```python
class Student:
    __slots__ = ('name', 'age')

    def __init__(self, name, age):
        self.name = name
        self.age = age


stu = Student('Кузнец', 20)
# AttributeError: 'Student' object has no attribute 'sex'
stu.sex = 'мужской'
```

### Статические методы и методы класса

Методы, которые мы определили в классе ранее, являются объектными методами, другими словами, эти методы - сообщения, которые может получать объект. Помимо объектных методов, классы могут иметь статические методы и методы класса, которые представляют собой сообщения, отправляемые классу, и между ними нет существенной разницы. В объектно-ориентированном мире все является объектом, и каждый класс, который мы определяем, на самом деле является объектом, а статические методы и методы класса - это сообщения, посылаемые объектам класса. Так какие же сообщения посылаются непосредственно объектам класса?

В качестве примера определим класс triangle, который строит треугольники, передавая длины трех сторон, и предоставляет методы для вычисления периметра и площади. Вычисление периметра и площади - это определенно метод объекта triangle, без сомнения. Однако при создании объекта треугольника переданные три стороны могут не построить треугольник, для чего мы можем сначала написать метод, проверяющий, что заданные длины трех сторон могут образовать треугольник. Этот метод явно не является методом объекта, поскольку объект треугольника еще не был создан при вызове этого метода. Мы можем оформить этот тип метода как статический метод или метод класса, то есть этот тип метода отправляется не в сообщение объекта треугольника, а в сообщение класса треугольника, код показан ниже.

```python
class Triangle(object):
    """Треугольники"""

    def __init__(self, a, b, c):
        """Методы инициализации"""
        self.a = a
        self.b = b
        self.c = c

    @staticmethod
    def is_valid(a, b, c):
        """Определите, могут ли три стороны образовать треугольник(статический метод)"""
        return a + b > c and b + c > a and a + c > b

    # @classmethod
    # def is_valid(cls, a, b, c):
    #     """Определите, могут ли три стороны образовать треугольник(метод класса)"""
    #     return a + b > c and b + c > a and a + c > b

    def perimeter(self):
        """Вычисление периметра"""
        return self.a + self.b + self.c

    def area(self):
        """Расчет площади"""
        p = self.perimeter() / 2
        return (p * (p - self.a) * (p - self.b) * (p - self.c)) ** 0.5
```

В приведенном выше коде метод `is_valid` объявлен как статический метод класса `Triangle` с помощью декоратора `staticmethod`. Если вы хотите объявить метод класса, то можете использовать декоратор `classmethod` (как показано в строках 15~18 приведенного выше кода). Можно вызвать метод класса напрямую, используя classname.MethodName для вызова статических методов и методов класса, разница между ними заключается в том, что первым параметром метода класса является сам объект класса, в то время как статический метод не имеет такого параметра. Подводя краткий итог, можно сказать, что **Объектные методы, методы класса и статические методы можно вызывать по имени класса. Разница в том, что первым параметром метода является обычный объект или объект класса, либо не принимающий сообщение объект**. Статический метод часто может быть написан как отдельная функция, поскольку он не привязан к конкретному объекту.

В качестве примечания, мы можем добавить декоратор `property` (встроенный тип Python) к методу выше, который вычисляет периметр и площадь треугольника, так что `perimeter` и `area` класса треугольника станут двумя свойствами, к которым больше не обращаются через вызов метода, а получают их напрямую, обращаясь к свойствам с помощью объекта, как показано в модифицированном варианте Модифицированный код показан ниже.

```python
class Triangle(object):
    """Треугольники"""

    def __init__(self, a, b, c):
        """Методы инициализации"""
        self.a = a
        self.b = b
        self.c = c

    @staticmethod
    def is_valid(a, b, c):
        """Определите, могут ли три стороны образовать треугольник(静态方法)"""
        return a + b > c and b + c > a and a + c > b

    @property
    def perimeter(self):
        """Вычисление периметра"""
        return self.a + self.b + self.c

    @property
    def area(self):
        """Расчет площади"""
        p = self.perimeter / 2
        return (p * (p - self.a) * (p - self.b) * (p - self.c)) ** 0.5


t = Triangle(3, 4, 5)
print(f'Периметр: {t.perimeter}')
print(f'Площадь: {t.area}')
```

### Наследование и полиморфизм

Объектно-ориентированные языки программирования поддерживают создание новых классов на основе существующих, что сокращает необходимость написания повторяющегося кода. Класс, предоставляющий информацию о наследовании, называется родительским классом (суперкласс, базовый класс), а класс, получающий информацию о наследовании, называется дочерним классом (производный класс). Например, если мы определим класс ученика и класс учителя, то обнаружим, что в них есть много повторяющегося кода, который представляет собой публичные атрибуты и поведение учителя и ученика как человеческих существ, поэтому в этом случае мы должны сначала определить человеческие существа, а затем с помощью наследования вывести классы учителя и ученика из человеческих существ, как показано в приведенном ниже коде.

```python
class Person:
    """Человек"""

    def __init__(self, name, age):
        self.name = name
        self.age = age
    
    def eat(self):
        print(f'{self.name} ест.')
    
    def sleep(self):
        print(f'{self.name} спит.')


class Student(Person):
    """Ученик"""
    
    def __init__(self, name, age):
        super().__init__(name, age)
    
    def study(self, course_name):
        print(f'{self.name} обучается {course_name}.')


class Teacher(Person):
    """Учитель"""

    def __init__(self, name, age, title):
        super().__init__(name, age)
        self.title = title
    
    def teach(self, course_name):
        print(f'{self.name}{self.title} обучает {course_name}.')



stu1 = Student('Бай Юаньфан', 21)
stu2 = Student('Ди Жэньцзе', 22)
tea1 = Teacher('У Цзэтянь', 35, 'доцент')
stu1.eat()
stu2.sleep()
tea1.eat()
stu1.study('Программирование на Python')
tea1.teach('Программирование на Python')
stu2.study('Введение в науку о данных')
```

Синтаксис наследования заключается в том, чтобы при определении класса указать родительский класс текущего класса в круглых скобках после имени класса. Если вы определяете класс, не указывая его родителя, то родителем по умолчанию будет класс `object`. Класс `object` является высшим классом в Python, что означает, что все классы являются его подклассами, прямо или косвенно. Язык Python допускает множественное наследование, что означает, что у класса может быть один или несколько родителей, и мы обсудим множественное наследование более подробно позже. В методе инициализации подкласса мы можем передать `super().__init__()`. Функция `super` - это одна из встроенных функций Python, предназначенная для получения объекта родительского класса текущего объекта. Как видно из приведенного выше кода, подклассы могут определять свои собственные свойства и методы в дополнение к тем, которые предоставляются родительским классом по наследству, поэтому подклассы имеют больше возможностей, чем их родители. На практике мы часто заменяем родительский объект объектом подкласса, что является обычным поведением в объектно-ориентированном программировании, известным также как "принцип замещения Лисков".

Подклассы могут переписать (перереализовать) метод после наследования его от родителя, а разные подклассы могут давать разные реализации одного и того же метода родителя, что будет проявлять полиморфное поведение (вызов одного и того же метода и выполнение разных действий) во время работы программы. Полиморфизм - самая важная часть объектно-ориентированного программирования, и, конечно, самая сложная для понимания и гибкого использования новичками. Мы объясним этот момент на специальных примерах в следующем разделе.

### Резюме

Python - динамически типизированный язык. Объекты в Python могут иметь свойства, добавляемые к ним динамически, а методы объекта фактически являются свойствами, за исключением того, что они соответствуют функции, которую можно вызвать. В объектно-ориентированном мире **все является объектом**, и классы, которые мы определяем, также являются объектами, поэтому **классы также могут получать сообщения**, а соответствующие методы являются методами класса или статическими методами. Благодаря наследованию мы **можем создавать новые классы** на основе существующих классов, что позволяет повторно использовать существующий код класса.
